# Правила работы с репозиторием

## Git — только по команде «гит»

- Никаких git-операций, которые меняют репозиторий (commit, push, merge, rebase и т.п.), пока пользователь явно не напишет слово **«гит»** (по-русски).
- После правок кода — остановиться и сообщить, что изменения не закоммичены.
- Если пользователь просит «закоммить», «опубликуй» и т.п. без слова «гит» — уточнить, а не делать.
- Чтение разрешено всегда: `git status`, `git diff`, `git log`.

### Куда коммитить по «гит»

- Оба помощника — и **веб-помощник** (Claude Code на claude.ai/code), и **локальный** (VS Code на компьютере пользователя) — работают прямо в `main`. Отдельных веток и PR не создавать.
- По «гит» — commit и push в `main`.
- Перед началом работы и перед коммитом — подтянуть свежий `main` (`git pull`), потому что второй помощник тоже пушит в `main`.

### Сообщения коммитов

- **Веб-помощник:** сообщение коммита пишется **на русском** и начинается со слова **`Web`**, например: `Web: добавлена кнопка обновления заказа`.
- Так в истории (`git log`, GitHub) сразу видно, какие изменения сделал веб-помощник.

**Почему:** пуш в `main` сразу публикует сайт — Cloudflare Pages (https://cruises-booking.pages.dev/) собирается автоматически из `main`. Пользователь сам решает, когда изменения уходят на сайт, и смотрит их через историю коммитов.

## Общение

- Пользователь пишет по-русски — отвечать по-русски.
- Пользователь переносит информацию между несколькими помощниками Claude (на десктопе и в вебе). Сообщения, предназначенные другому помощнику, писать самодостаточными, чтобы их можно было скопировать целиком.
- Перед изменениями — сначала изучить код и объяснить, что понял, если пользователь об этом просит.
